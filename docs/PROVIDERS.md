# Delivery contracts and live gates

No live sends have been performed. Local providers persist synthetic acceptances in D1; they do not pretend to be delivered. Delivery requires a separate verified receipt. All message states and failure reasons appear in the merchant notification view. Six failed attempts become final failures and create an operations alert; retries use exponential backoff.

Email uses Resend POST /emails with a stable Idempotency-Key. Automatic/operator retries stop within 23 hours of first submission, inside Resend's 24-hour key lifetime. Signed Svix receipts check the raw body and a five-minute timestamp tolerance. Meta uses a configured Graph API version, phone-number ID and per-event approved template. Each template must accept one body parameter containing the French message. Authentication email is platform transactional email; other email and WhatsApp connections must be enabled for each tenant.

WhatsApp has no assumed request-idempotency guarantee. Timeouts, ambiguous 5xx and expired send leases enter `uncertain`, never automatic resend or fallback. A signed receipt carrying `biz_opaque_callback_data` can reconcile that job. Definitive rejection permits an independently keyed email fallback only when email consent was recorded. An email fallback is a separate observable job. Messages already accepted externally cannot be recalled after cancellation or unsubscribe.

APP_SECRET protects encrypted outbox payloads and signed links. PROVIDER_KEK protects per-tenant access tokens using AES-GCM with a fresh IV and a versioned envelope. Provider secrets are never returned through config APIs. Production mock providers fail closed. Real secrets must be set out of band by the owner; do not put them in source or CI.

Owner actions before live testing: provision approved Cloudflare environment; set APP_SECRET, PROVIDER_KEK, EMAIL_FROM, RESEND_API_KEY and RESEND_WEBHOOK_SECRET; verify the sender domain; select EMAIL_PROVIDER=resend. Complete Meta business/phone/template onboarding; set META_APP_SECRET and META_VERIFY_TOKEN, select WHATSAPP_PROVIDER=meta, configure the tenant's token/phone/API version/approved template map. Verify callback signatures and observe accepted and delivered events on an explicitly opted-in test address/phone. Confirm template category, actual pricing, number coexistence and privacy requirements with the owner before launch. These are BLOCKED live gates, not completed features.

References checked 2026-10-08: [Resend send contract](https://resend.com/docs/api-reference/emails/send-email), [Resend signature verification](https://resend.com/docs/webhooks/verify-webhooks-requests). Meta documentation could not be fetched in this environment; the adapter's fixture contract and current app/version/template requirements must be checked in the owner's Meta dashboard before a live test.
